
                  SQL Clauses – Interview Questions (Theory & Technical)

-- 1. What is a clause in SQL?

          A clause in SQL is a part of an SQL statement that performs a specific function, such as filtering data, sorting results, grouping records, or specifying conditions.

SQL clauses help define what data to retrieve and how to process it.

| **Clause** | **Purpose**                               | **Example**                   |
| ---------- | ----------------------------------------- | ----------------------------- |
| `SELECT`   | Specifies the columns to retrieve         | `SELECT Name FROM Employees;` |
| `FROM`     | Specifies the table to retrieve data from | `FROM Employees`              |
| `WHERE`    | Filters rows based on conditions          | `WHERE Salary > 50000`        |
| `GROUP BY` | Groups rows with similar values           | `GROUP BY Department`         |
| `HAVING`   | Filters grouped data                      | `HAVING COUNT(*) > 5`         |
| `ORDER BY` | Sorts the result set                      | `ORDER BY Salary DESC`        |
| `LIMIT`    | Restricts the number of rows returned     | `LIMIT 10`                    |


Example SQL Query with Clauses:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
WHERE Salary > 30000
GROUP BY Department
HAVING COUNT(*) > 5
ORDER BY Employee_Count DESC;

In this query:

SELECT chooses the columns.
FROM identifies the table.
WHERE filters records.
GROUP BY creates groups.
HAVING filters groups.
ORDER BY sorts the output.
Summary:

A SQL clause is a component of an SQL statement that controls data selection, filtering, grouping, sorting, and other operations to produce the required result.

-- 2. Why are SQL clauses used in SQL queries?

          SQL clauses are used in SQL queries to control how data is retrieved, filtered, organized, and processed from database tables. They allow users to specify exactly what information they need and how the results should be displayed.

Reasons SQL Clauses Are Used:

To Select Specific Data

The SELECT clause determines which columns should be retrieved.
SELECT Name, Salary
FROM Employees;

To Filter Records

The WHERE clause retrieves only rows that meet specific conditions.
SELECT *
FROM Employees
WHERE Department = 'IT';

To Group Data

The GROUP BY clause combines rows with similar values for analysis.
SELECT Department, COUNT(*)
FROM Employees
GROUP BY Department;

To Filter Groups

The HAVING clause applies conditions to grouped results.
SELECT Department, COUNT(*)
FROM Employees
GROUP BY Department
HAVING COUNT(*) > 10;

To Sort Results

The ORDER BY clause arranges output in ascending or descending order.
SELECT *
FROM Employees
ORDER BY Salary DESC;

To Control the Number of Results

Clauses like LIMIT restrict the number of rows returned.
SELECT *
FROM Employees
LIMIT 5;
Summary:

SQL clauses are used to:

Retrieve required data
Apply filters and conditions
Group and summarize information
Sort results
Control output size
Make queries more precise and efficient

They are essential for writing effective and meaningful SQL queries.

-- 3. What are the different types of SQL clauses? Explain each briefly.

         The different types of SQL clauses are parts of an SQL query that help define how data is retrieved, filtered, grouped, sorted, and displayed.

1. SELECT Clause
Used to specify the columns or expressions to retrieve from a table.
It is the main clause used to fetch data.

Example:

SELECT Name, Salary
FROM Employees;
2. FROM Clause
Specifies the table or tables from which data should be retrieved.

Example:

SELECT *
FROM Employees;
3. WHERE Clause
Filters rows based on a specified condition.
Only records that satisfy the condition are returned.

Example:

SELECT *
FROM Employees
WHERE Salary > 50000;
4. GROUP BY Clause
Groups rows with the same values in specified columns.
Commonly used with aggregate functions like COUNT(), SUM(), and AVG().

Example:

SELECT Department, COUNT(*)
FROM Employees
GROUP BY Department;
5. HAVING Clause
Filters groups created by the GROUP BY clause.
Used with aggregate functions.

Example:

SELECT Department, COUNT(*)
FROM Employees
GROUP BY Department
HAVING COUNT(*) > 10;
6. ORDER BY Clause
Sorts the result set in ascending (ASC) or descending (DESC) order.

Example:

SELECT *
FROM Employees
ORDER BY Salary DESC;
7. LIMIT / TOP Clause
Restricts the number of rows returned by a query.
Syntax depends on the database system.

Example (MySQL):

SELECT *
FROM Employees
LIMIT 10;
8. JOIN Clause
Combines data from two or more tables based on a related column.

Example:

SELECT Employees.Name, Departments.Department_Name
FROM Employees
JOIN Departments
ON Employees.Department_ID = Departments.ID;
9. DISTINCT Clause
Removes duplicate values from the result.

Example:

SELECT DISTINCT Department
FROM Employees;

-- 4. What is the difference between the SELECT clause and the FROM clause?

The SELECT clause and the FROM clause serve different purposes in an SQL query.

| **SELECT Clause**                                                    | **FROM Clause**                                                        |
| -------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| Specifies **which columns or expressions** to display in the result. | Specifies **which table or tables** the data should be retrieved from. |
| Controls the output of the query.                                    | Defines the source of the data.                                        |
| Appears at the beginning of an SQL query.                            | Comes after the `SELECT` clause.                                       |

Example:
SELECT Name, Salary
FROM Employees;

In this query:

SELECT Name, Salary → Chooses the columns to display.
FROM Employees → Specifies the table from which the data is retrieved.
Another Example:
SELECT *
FROM Customers;
SELECT * → Retrieves all columns.
FROM Customers → Retrieves data from the Customers table.
Summary:
SELECT → Defines what data you want to see.
FROM → Defines where the data comes from.

-- 5. What is the purpose of the WHERE clause? Can it be used without the SELECT clause?

         The WHERE clause is used to filter rows in a table based on a specified condition. It returns only the records that satisfy the given condition.

Example:
SELECT *
FROM Employees
WHERE Department = 'IT';

In this query:

WHERE Department = 'IT' filters the results.
Only employees belonging to the IT department are returned.
Can WHERE be used without the SELECT clause?

No, the WHERE clause cannot be used alone. It must be part of a complete SQL statement and is commonly used with clauses such as SELECT, UPDATE, and DELETE.

Examples:

Using WHERE with UPDATE:

UPDATE Employees
SET Salary = 60000
WHERE Employee_ID = 101;

Using WHERE with DELETE:

DELETE FROM Employees
WHERE Employee_ID = 101;
Summary:
WHERE → Filters rows based on conditions.
It cannot be used as a standalone clause.
It is commonly used with SELECT, UPDATE, and DELETE statements.

-- 6. What is the difference between the WHERE clause and the HAVING clause?

   The WHERE clause and the HAVING clause are both used to filter data, but they are applied at different stages of query execution.
| **WHERE Clause**                                                                     | **HAVING Clause**                           |
| ------------------------------------------------------------------------------------ | ------------------------------------------- |
| Filters individual rows before grouping.                                             | Filters groups after `GROUP BY` is applied. |
| Cannot usually be used with aggregate functions like `COUNT()`, `SUM()`, or `AVG()`. | Commonly used with aggregate functions.     |
| Applied before `GROUP BY`.                                                           | Applied after `GROUP BY`.                   |

 Example using WHERE:
SELECT Department, Salary
FROM Employees
WHERE Salary > 50000;

This filters individual employee records where the salary is greater than 50,000.

Example using HAVING:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
GROUP BY Department
HAVING COUNT(*) > 10;

This filters groups and displays only departments having more than 10 employees.

Query Execution Order (simplified):
FROM → Select tables
WHERE → Filter rows
GROUP BY → Create groups
HAVING → Filter groups
SELECT → Choose output columns
ORDER BY → Sort results

Summary:
WHERE → Filters rows before grouping.
HAVING → Filters groups after aggregation.
Use WHERE for normal conditions and HAVING for conditions involving aggregate functions.

--7. What is the purpose of the GROUP BY clause? When should it be used?

          The GROUP BY clause is used in SQL to combine rows with the same values into groups. It is mainly used with aggregate functions such as COUNT(), SUM(), AVG(), MAX(), and MIN() to perform calculations on each group.

Purpose of GROUP BY:
Organizes similar records into groups.
Allows summary calculations for each group.
Helps generate reports and analyze data.

Example:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
GROUP BY Department;

Result:

Department   Employee_Count
IT           20
HR           10
Sales        15

Here, employees are grouped by department, and the number of employees in each department is calculated.

When should GROUP BY be used?

Use GROUP BY when you need to:

Calculate totals or averages for categories.
Generate summary reports.
Find counts of records in different groups.
Analyze data based on common values.
More Examples:

Average salary by department:

SELECT Department, AVG(Salary) AS Average_Salary
FROM Employees
GROUP BY Department;

Total sales by product:

SELECT Product_ID, SUM(Amount) AS Total_Sales
FROM Sales
GROUP BY Product_ID;

Summary:
GROUP BY → Groups rows with similar values.
Used with aggregate functions to summarize data.
Commonly used in reports, analytics, and business data analysis.

-- 8. Why is the HAVING clause used after the GROUP BY clause?

           The HAVING clause is used after the GROUP BY clause because it filters groups of data after aggregation has been performed.

When SQL executes a query:

FROM → Retrieves data from tables.
WHERE → Filters individual rows.
GROUP BY → Creates groups from the filtered rows.
HAVING → Filters those created groups based on aggregate results.

Example:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
GROUP BY Department
HAVING COUNT(*) > 10;

How it works:

GROUP BY Department creates groups for each department.
COUNT(*) calculates the number of employees in each department.
HAVING COUNT(*) > 10 keeps only departments with more than 10 employees.
Why not use WHERE?

The WHERE clause filters rows before grouping, so it cannot filter results of aggregate functions.

Incorrect:

SELECT Department, COUNT(*)
FROM Employees
WHERE COUNT(*) > 10
GROUP BY Department;

This fails because COUNT(*) is calculated after the WHERE stage.

Summary:
GROUP BY creates groups.
HAVING filters those groups.
It is placed after GROUP BY because it works on aggregated data rather than individual rows.

-- 9. What is the difference between the DISTINCT clause and the GROUP BY clause?

              The DISTINCT clause and the GROUP BY clause are both used to handle duplicate values, but they serve different purposes



| **DISTINCT Clause**                              | **GROUP BY Clause**                                                 |
| ------------------------------------------------ | ------------------------------------------------------------------- |
| Removes duplicate rows from the result.          | Groups rows with the same values for aggregation and analysis.      |
| Mainly used to return unique values.             | Used with aggregate functions like `COUNT()`, `SUM()`, and `AVG()`. |
| Does not perform calculations on groups.         | Performs calculations on each group.                                |
| Simpler and faster for only removing duplicates. | Used for generating summaries and reports.                          |

   Example using DISTINCT:
SELECT DISTINCT Department
FROM Employees;

Purpose: Returns each department only once.

Result:

IT
HR
Sales
Example using GROUP BY:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
GROUP BY Department;

Purpose: Groups employees by department and counts employees in each group.

Result:

IT      20
HR      10
Sales   15
Summary:
DISTINCT → Removes duplicate values and returns unique records.
GROUP BY → Creates groups and is used for calculations and data analysis.
Use DISTINCT for finding unique values and GROUP BY when you need summarized information.

-- 10. What is the purpose of the ORDER BY clause? What is the default sorting order in SQL?

             The ORDER BY clause is used in SQL to sort the result set of a query based on one or more columns. It can arrange data in either ascending or descending order.

Syntax:
SELECT column_name
FROM table_name
ORDER BY column_name [ASC | DESC];
Example:

Ascending order:

SELECT Name, Salary
FROM Employees
ORDER BY Salary ASC;

This sorts employees from the lowest salary to the highest salary.

Descending order:

SELECT Name, Salary
FROM Employees
ORDER BY Salary DESC;

This sorts employees from the highest salary to the lowest salary.

Default Sorting Order:

The default sorting order in SQL is ascending order (ASC).

Example:

SELECT *
FROM Employees
ORDER BY Name;

This is treated as:

SELECT *
FROM Employees
ORDER BY Name ASC;

Summary:
ORDER BY → Sorts query results.
ASC → Ascending order (default).
DESC → Descending order.
If no sorting direction is specified, SQL uses ascending order by default.

-- 11. What is the use of the LIMIT clause? How is it useful in real-time applications?

          The LIMIT clause is used in SQL to restrict the number of rows returned by a query. It is commonly used when you only need a specific number of records instead of retrieving the entire result set.

Syntax:
SELECT column_name
FROM table_name
LIMIT number_of_rows;
Example:
SELECT *
FROM Employees
LIMIT 10;

This query returns only the first 10 rows from the Employees table.

Real-Time Applications of LIMIT:
1. Pagination in Applications

Used to display data page by page in websites and mobile apps.

Example:

SELECT *
FROM Products
LIMIT 20 OFFSET 40;

This retrieves 20 products starting from the 41st record (page 3 in many pagination systems).

2. Displaying Top Results

Used to show top records based on sorting.

Example:

SELECT Name, Salary
FROM Employees
ORDER BY Salary DESC
LIMIT 5;

This retrieves the top 5 highest-paid employees.

3. Improving Performance

When tables contain millions of records, retrieving only required rows reduces:

Database processing time
Network data transfer
Application memory usage
4. Search Result Pages

Used in applications like:

E-commerce websites (showing products per page)
Social media feeds (loading a limited number of posts)
Banking applications (showing recent transactions)
Note:
LIMIT is commonly used in MySQL and PostgreSQL.
Other databases use similar features:
SQL Server → TOP
Oracle → FETCH FIRST / ROWNUM
Summary:

The LIMIT clause controls the number of rows returned by a query and is widely used for pagination, displaying top results, improving performance, 
and managing large datasets in real-time applications.

-- 12. What is the SQL query execution order? Why is it different from the order in which we write the query?

           The SQL query execution order is the sequence in which the database engine processes the clauses of a SQL query. It is different from the order
 in which we write the query because SQL is written in a human-readable format, while the database follows a logical processing order to efficiently retrieve and process data.

| **Execution Order** | **Clause**         | **Purpose**                                        |
| ------------------- | ------------------ | -------------------------------------------------- |
| 1                   | `FROM`             | Identifies the table(s) and retrieves source data. |
| 2                   | `JOIN`             | Combines data from multiple tables.                |
| 3                   | `WHERE`            | Filters individual rows.                           |
| 4                   | `GROUP BY`         | Groups rows based on column values.                |
| 5                   | `HAVING`           | Filters groups after aggregation.                  |
| 6                   | `SELECT`           | Chooses columns and expressions to display.        |
| 7                   | `DISTINCT`         | Removes duplicate rows.                            |
| 8                   | `ORDER BY`         | Sorts the result set.                              |
| 9                   | `LIMIT` / `OFFSET` | Restricts the number of rows returned.             |

Example Query:
SELECT Department, COUNT(*) AS Total_Employees
FROM Employees
WHERE Salary > 30000
GROUP BY Department
HAVING COUNT(*) > 5
ORDER BY Total_Employees DESC
LIMIT 10;


Execution Process:
FROM → Gets data from Employees.
WHERE → Removes employees with salary ≤ 30,000.
GROUP BY → Groups remaining employees by department.
HAVING → Keeps only departments with more than 5 employees.
SELECT → Calculates and displays department and employee count.
ORDER BY → Sorts by employee count.
LIMIT → Returns only the top 10 results.

Why is Execution Order Different from Writing Order?

SQL queries are written in a way that is easier for humans to understand:

SELECT
FROM
WHERE
GROUP BY
HAVING
ORDER BY

But the database must first know where the data comes from (FROM) before it can filter, group, and select the required information.

Summary:
Written order: SELECT → FROM → WHERE → GROUP BY → HAVING → ORDER BY
Execution order: FROM → JOIN → WHERE → GROUP BY → HAVING → SELECT → ORDER BY → LIMIT
The difference exists because SQL uses a logical processing sequence optimized for efficient data retrieval.


-- 13. Can we use multiple SQL clauses in a single query? Explain with an example scenario.

     Yes, we can use multiple SQL clauses in a single query. In real-world applications, queries often combine clauses like SELECT, FROM, WHERE, GROUP BY, HAVING, and ORDER BY to retrieve, filter, summarize, and sort data according to business requirements.

Example Scenario:

A company wants to find the top 5 departments with more than 10 employees whose average salary is above 50,000.

SELECT Department, AVG(Salary) AS Average_Salary, COUNT(*) AS Employee_Count
FROM Employees
WHERE Status = 'Active'
GROUP BY Department
HAVING AVG(Salary) > 50000
   AND COUNT(*) > 10
ORDER BY Average_Salary DESC
LIMIT 5;

How the Clauses Work:
FROM
Retrieves data from the Employees table.
WHERE
Filters only active employees.
GROUP BY
Groups employees based on their department.
HAVING
Filters departments where:
Average salary is greater than 50,000.
Employee count is greater than 10.
SELECT
Displays department name, average salary, and employee count.
ORDER BY
Sorts departments by average salary in descending order.
LIMIT
Returns only the top 5 departments.

Summary:

Using multiple SQL clauses in one query helps to:

Filter required data
Perform calculations
Generate reports
Apply business rules
Control and format output

Complex real-time applications such as banking reports, sales analytics, dashboards, and customer management systems commonly use multiple SQL clauses together.

-- 14. Which SQL clauses are executed before the SELECT clause, and why?

The SQL clauses that are executed before the SELECT clause are:

FROM
JOIN
WHERE
GROUP BY
HAVING

| Execution Order | Clause     | Purpose                                            |
| --------------- | ---------- | -------------------------------------------------- |
| 1               | `FROM`     | Identifies the source table(s) and retrieves data. |
| 2               | `JOIN`     | Combines data from multiple tables.                |
| 3               | `WHERE`    | Filters individual rows based on conditions.       |
| 4               | `GROUP BY` | Creates groups of rows for aggregation.            |
| 5               | `HAVING`   | Filters groups based on aggregate results.         |
| 6               | `SELECT`   | Chooses the columns and expressions to display.    |


Why are they executed before SELECT?

The database must first determine which data is available and which rows should be processed before deciding what columns or calculated values should appear in the final output.

Example:
SELECT Department, COUNT(*) AS Employee_Count
FROM Employees
WHERE Salary > 40000
GROUP BY Department
HAVING COUNT(*) > 5;

Execution process:

FROM → Accesses the Employees table.
WHERE → Removes employees with salary ≤ 40,000.
GROUP BY → Groups the remaining employees by department.
HAVING → Keeps only departments with more than 5 employees.
SELECT → Displays the department and employee count.
Summary:

Clauses like **FROM, JOIN, WHERE, GROUP BY, and HAVING execute before SELECT because SQL must first prepare and filter the data before selecting the final output columns.

-- 15. Which SQL clauses are commonly used together while generating business reports and dashboards? Explain their purpose.

   When generating business reports and dashboards, multiple SQL clauses are commonly used together to retrieve, filter, summarize, and present data in a meaningful way.

| **Clause**     | **Purpose in Reporting**                                                      |
| -------------- | ----------------------------------------------------------------------------- |
| **`SELECT`**   | Chooses the columns, calculations, and metrics to display.                    |
| **`FROM`**     | Specifies the table(s) from which data is collected.                          |
| **`JOIN`**     | Combines data from multiple tables (e.g., customers, orders, products).       |
| **`WHERE`**    | Filters data based on specific conditions (e.g., date range, region, status). |
| **`GROUP BY`** | Groups data for summaries and analysis.                                       |
| **`HAVING`**   | Filters grouped results based on calculated values.                           |
| **`ORDER BY`** | Sorts results for better presentation.                                        |
| **`LIMIT`**    | Restricts the number of records displayed.                                    |


Example Scenario:

A sales dashboard needs to show total sales by region for active customers with sales above a certain amount.

SELECT Region, SUM(Sales_Amount) AS Total_Sales
FROM Customers
JOIN Orders
ON Customers.Customer_ID = Orders.Customer_ID
WHERE Customers.Status = 'Active'
GROUP BY Region
HAVING SUM(Sales_Amount) > 100000
ORDER BY Total_Sales DESC;

How Each Clause Helps:
FROM + JOIN
Collects data from related tables such as customers and orders.

WHERE
Filters only active customers.

GROUP BY
Creates groups by region.

Aggregate Functions (SUM)
Calculates total sales for each region.

HAVING
Shows only regions meeting the sales target.

ORDER BY
Displays regions from highest to lowest sales.

SELECT
Defines the final information shown in the dashboard.

Summary:

Business reports and dashboards commonly combine:

SELECT + FROM + JOIN + WHERE + GROUP BY + HAVING + ORDER BY

These clauses help transform raw database records into useful business insights such as sales reports, customer analysis, financial summaries, and performance dashboards.
